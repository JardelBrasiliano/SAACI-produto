1. Requisitos Funcionais

1.1 Cadastro e Login

IDRequisitoEscopo
RF01O sistema deve permitir o cadastro exclusivamente com e-mail institucional do IF.MVP
RF02O sistema deve validar o domínio do e-mail, rejeitando e-mails não institucionais.MVP
RF03O sistema deve enviar um link de confirmação ao e-mail após o cadastro.MVP
RF04O sistema deve ativar a conta somente após a confirmação do e-mail.MVP
RF05O sistema deve restringir contas não verificadas à tela de verificação, onde o aluno só pode reenviar o link de confirmação (RF39) ou corrigir o e-mail cadastrado (RF40).MVP
RF06O sistema deve permitir o login de usuários com conta verificada. O login de uma conta não verificada leva direto à tela de verificação (RF05).MVP
RF07O sistema deve permitir o encerramento da sessão (logout).MVP
RF08O sistema deve permitir recuperação/redefinição de senha via e-mail institucional.MVP
RF39O sistema deve permitir que o aluno com conta não verificada peça o reenvio do link de confirmação. Ao reenviar, a tela mostra uma dica com o e-mail para o qual o link foi enviado e orienta a procurar no spam ou na lixeira caso ele não esteja na caixa de entrada. Entre um reenvio e outro há um intervalo mínimo, e a tela mostra quanto falta para poder pedir de novo.MVP
RF40Enquanto a conta não estiver verificada, o sistema deve permitir que o aluno corrija o e-mail cadastrado, respeitando RF01 e RF02. O link de confirmação passa a ser enviado para o novo e-mail.MVP

1.2 Perfil com Informações do Curso

IDRequisitoEscopo
RF09O sistema deve registrar e exibir as informações do curso do usuário (departamento, curso e semestre).MVP
RF10O sistema deve permitir a edição das informações do perfil.Opcional
RF11O sistema deve registrar e exibir o semestre de início do usuário.MVP

1.3 Registro de Horas Complementares

IDRequisitoEscopo
RF13O sistema deve permitir que o usuário registre suas horas complementares.MVP
RF14O sistema deve calcular automaticamente as horas com base nas regras da instituição ou do curso. As horas de cada atividade não são arredondadas (ex.: 10h de curso na razão 1:4 contam 2,5h). Só o total geral é arredondado, sempre para baixo (ex.: 119,5h viram 119h).MVP
RF15O sistema deve manter as regras de cálculo por curso, permitindo diferentes critérios (parametrização por matriz/curso, ver RNF21). Curso-piloto: Engenharia de Computação, cujas regras estão em regras-engenharia-computacao.md. Segundo curso para provar a parametrização: Engenharia de Telecomunicações.MVP
RF16O sistema deve exibir o total acumulado e o progresso em relação à carga horária exigida, por categoria.MVP
RF17O sistema deve permitir visualizar, editar e remover os registros de horas.Opcional
RF31O sistema deve permitir anexar um arquivo de comprovante (certificado) ao registrar uma atividade.MVP
RF32O sistema deve exibir ao aluno, antes do envio, a regra de conversão aplicada ao tipo de atividade escolhido (ex., em Engenharia de Computação: "curso de 8h na área do curso = 2h computadas"), evitando que ele descubra a proporção só depois de registrar.MVP
RF35Para cada categoria de horas complementares, o sistema deve exibir os certificados que a compõem, quantas horas cada um contribui para aquela categoria, o total por categoria e o total geral de horas contabilizadas.MVP
RF36O sistema deve permitir selecionar um ou mais certificados já registrados (ou todos) e baixá-los com o número do item da categoria no nome do arquivo (ex.: item-07_curso-python.pdf), para o aluno usar no preenchimento do protocolo de solicitação de validação junto à coordenação.MVP
RF37O sistema deve exibir uma tela no formato do formulário de solicitação de atividades complementares do curso do aluno, com a carga horária solicitada de cada item já preenchida a partir dos registros (respeitando o máximo do item), e um passo a passo de como preencher o formulário oficial e entregá-lo à coordenação.MVP
RF38O sistema deve pedir a data da atividade no registro e, quando ela for anterior ao semestre de início do aluno (RF11), avisar antes do envio que a atividade não será contabilizada, porque só contam atividades feitas depois do ingresso no curso.MVP

1.4 Conta e Dados Pessoais (LGPD)

IDRequisitoEscopo

RF34Antes de excluir a conta, o sistema deve oferecer a opção de baixar os dados já armazenados (certificados e registros de horas).Opcional

2. Requisitos Não Funcionais

2.1 Segurança

IDRequisito
RNF01As senhas devem ser armazenadas com hash e salt, nunca em texto puro.
RNF02Toda comunicação entre cliente e servidor deve ocorrer por HTTPS.
RNF03O link de confirmação de e-mail deve ter validade limitada e ser de uso único. Quando um novo link é enviado (RF39, RF40), os anteriores deixam de valer.
RNF04O acesso deve exigir autenticação; cada usuário só pode acessar/alterar seus próprios dados. Arquivos de comprovante só podem ser acessados pelo dono, nunca por endereço público.

2.2 Privacidade e Conformidade

IDRequisito
RNF05O tratamento de dados pessoais deve estar em conformidade com a LGPD (Lei nº 13.709/2018). Na exclusão de conta (RF33), dados e arquivos de comprovante devem ser apagados de forma definitiva, incluindo cópias de segurança, num prazo informado ao aluno no momento da exclusão.
RNF06O sistema deve coletar apenas os dados necessários (minimização de dados).

2.3 Usabilidade e Acessibilidade

IDRequisito
RNF12A interface deve ser intuitiva, permitindo concluir as tarefas principais sem treinamento. Critério: em teste com pelo menos 5 alunos do curso que nunca usaram o sistema, cada um registra uma atividade e descobre quanto falta para completar a carga horária exigida, sem ajuda.
RNF13As mensagens de erro devem ser claras e orientar o usuário sobre como corrigir a ação.
RNF23A interface deve considerar usuários com dificuldade de acesso à tecnologia e neurodivergentes, evitando jargão de sistema e fluxos com etapas escondidas. Critérios concretos em ../design-system/principios-ui.html.

2.4 Desempenho

IDRequisito
RNF14As telas principais devem carregar em até 3 segundos em condições normais de rede.
RNF15O e-mail de verificação deve ser disparado em até 1 minuto após o cadastro ou o pedido de reenvio.

2.5 Compatibilidade e Portabilidade

IDRequisito
RNF17A interface deve ser responsiva, funcionando em dispositivos desktop e mobile.
RNF18O sistema deve ser compatível com as versões atuais dos principais navegadores.
RNF25O sistema deve aceitar comprovantes em PDF, JPG e PNG. O limite de tamanho do arquivo deve aparecer ao aluno antes do envio e deve permitir, no mínimo, uma foto de certificado tirada com a câmera de um celular comum.

2.6 Disponibilidade e Confiabilidade

IDRequisito
RNF19O sistema deve ter meta de disponibilidade adequada ao contexto acadêmico (ex.: ≥ 99% no horário letivo).
RNF20O cálculo de horas deve produzir resultados consistentes e reproduzíveis: os mesmos registros dão sempre o mesmo resultado, e os totais exibidos no painel (RF16), no resumo por categoria (RF35) e no formulário (RF37) saem do mesmo cálculo.
RNF24Um registro de atividade deve ser salvo completo (dados e comprovante) ou não ser salvo. Se a conexão cair durante o envio, o que o aluno já preencheu deve continuar no aparelho, e o sistema deve informar o que foi salvo e o que não foi.

2.7 Manutenibilidade e Integração

IDRequisito
RNF21As regras de cálculo de horas por curso devem ser parametrizáveis, sem alterar o código-fonte.
